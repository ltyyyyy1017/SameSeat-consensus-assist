# 同席的现成字幕底座

同席把开发重心放在“信息呈现进度—具体决定—回应机会—人工处理”上。语音识别、语音端点检测和自动标点复用开源项目，不训练识别模型，也不用语言模型把听不清的原话润色成另一句话。

## 检索结果与选择

| 项目 | 适合之处 | 对当前项目的取舍 |
| --- | --- | --- |
| [FunASR](https://github.com/modelscope/FunASR) | 有中文识别、VAD、标点和两遍识别服务；可将实时初稿与句末校正结合 | 保留为后续独立字幕服务的选项。完整 C++ 两遍服务的部署与协议，比当前 Windows 单机原型更重 |
| [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) | 有 Windows Python 预编译包，提供 SenseVoice、Silero VAD 和官方麦克风示例，可离线运行 | 当前接入：SenseVoiceSmall int8 + Silero VAD，复用模型自身的中文标点输出 |
| [WhisperLiveKit](https://github.com/QuentinFuxa/WhisperLiveKit) | 有完整实时字幕服务、流式后端与多种识别模型 | 保留为需要逐字临时字幕、更多会议功能时的候选。仅换实时外壳，不代表原 Whisper 模型对当前中文语音的错误会消失 |

选择依据是当前运行环境和接入范围，不是对三者中文准确率的排名。没有开展相同真人录音下的完整对比评测。

## 实际接入方式

1. 浏览器 AudioWorklet 连续发送 16 kHz、单声道 PCM；收音只做浏览器自带的降噪、回声消除和采样率转换。
2. 主机用官方 Silero VAD 检测语音端点。去掉旧版浏览器的固定音量阈值、8 秒切段和“两段排队就停录”逻辑。
3. SenseVoice 在端点后识别语音，启用 `use_itn=True`，得到模型输出的中文标点和数字形式。按结果已有的句号、问号、叹号分成独立原句。
4. 每句字幕通过既有房间事务提交，保留原句编号、版本、纠错、议题依据、播报和留位流程；最终文字仍可人工修订。
5. 停止录音时先提交 AudioWorklet 的不足一帧尾音，再通知 VAD 完成末段，收到完成回执后才结束。模型或连接异常明确提示，不伪造字幕。

这是**持续收音、停顿后出句**的接法。当前不会边说边输出逐字临时字幕。语音端点是声学停顿，文本断句依赖模型标点，两者分开处理。VAD 的长语音保护上限为 25 秒，不能把连续无停顿讲话描述为无限上下文识别。

首次运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ai.txt
.\.venv\Scripts\python.exe scripts/setup_asr.py
```

`setup_models.py` 已包含该准备步骤。现有电脑已安装组件并下载模型。模型文件及许可证保存在 `.runtime/asr/`，下载来源、固定模型版本和本地 SHA-256 写入同目录 `manifest.json`；运行时不自动访问模型网站。`TONGXI_ASR_MODEL` 如有设置，现应指向包含 `model.int8.onnx`、`tokens.txt`、`silero_vad.onnx` 的目录。

## 需要保留的边界

现成模型仍可能误识别含糊发音、快速连读、背景噪声、否定词和方案字母。当前只对公开中文样例、合成语音和浏览器合成麦克风做了接入检查，结果保存在 `artifacts/asr-replacement-check.json` 与 `artifacts/browser-check.json`，不将其作为真人讨论准确率。后续只需用实际使用场景做小规模验收；若效果不合格，再替换独立识别底座，无需改动协商机制。

核心创新仍是：决定与有效原句版本关联、按个人授权保留议题回应机会、将补充带回原议题并形成明确人工处理。字幕底座作为依赖注明来源。
